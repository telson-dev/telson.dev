SSH vs API

为什么不用「直接 SSH 执行命令」？

给 AI 一把 root，和给它一把有权限范围的 API Key，是两件完全不同的事。

01

面板用户本来就没有 shell

Pterodactyl / Pelican 的典型用户拿到的是面板账号和受限 API Key，而不是节点上的 root。面板存在的意义就是把操作系统隔离掉。

02

最小权限

只读模式、危险操作二次确认、权限边界由 API Key 决定。AI 只能做你允许它做的事，而不是拥有一台机器的全部能力。

03

该走 API 的就走 API

备份、文件、电源状态在面板里都是有权限、有审计、有状态语义的一等操作，不是随手一条 shell 命令。

能做什么

▤

服务器总览

列出全部服务器，读取在线状态与资源占用。

⏻

电源控制

启动、停止、重启、强杀，动作后轮询状态直到就绪。

>_

控制台

直接向服务器发送指令，读回控制台输出。

▢

文件管理

浏览、读取、写入、上传、重命名、删除、新建文件夹、生成一次性下载链接。

▣

备份

查看备份列表、创建新备份、从备份恢复、删除旧备份。

◉

玩家在线

从控制台日志解析玩家进出，直接回答「现在谁在线」，兼容主流服务端日志格式。

🚨

崩服检测与告警

状态级 + 日志级崩溃信号检测（OOM / JVM / 异常退出 / 致命错误），可配 webhook / 邮件通知、冷却去重、连续确认防误报。

⇄

批量操作

一次列出全部服务器状态摘要，批量开机 / 关机 / 重启，单台失败不阻断整体。

◈

安全开关

只读模式一键开启，高危操作需要二次确认，API Key 永不离开本机。

开始使用

三分钟接入

需要 Python 3.12+。用 uv 一行跑起来，然后在 MCP 客户端里加一段配置即可。

命令行 
# 需要 Python 3.12+ 与 uv
$ uvx pteropilot

先看一眼版本：pteropilot --version 会打印「pteropilot v0.2.34（45 个 MCP 工具）」。工具数比上面的清单少，说明装到了旧版——PyPI 上的包有时滞后，最新 wheel 在 GitHub Releases，下下来 uv tool install <文件>.whl 即可。

连不上？先自检 
$ pteropilot --help

$ pteropilot --doctor

pteropilot v0.2.34（45 个 MCP 工具）
Python 3.12.7　Linux x86_64
版本：v0.2.34（已是最新）

结论：配置不完整，先补齐下面的项：
  ✗ 未设置 PANEL_URL
  ✗ 未设置 PANEL_API_KEY
  · 面板「账户 → API 凭证」生成客户端密钥（ptlc_ / pacc_）

一条命令查完：版本与工具数、Python 版本、PANEL_URL 有没有被自动规范化、密钥前缀与长度、面板连不连得上。输出不含密钥本身，可以直接贴到 issue 里。加 --no-network 只查配置不联网；全部正常时退出码 0，有问题 1。

  • API Key 在面板的 Account → API Credentials 里生成
  • 先用只读模式跑一遍，确认行为符合预期再放开

从源码运行（开发者）

# 需要 git、uv 与 Python 3.12+
$ git clone https://github.com/telson-dev/pteropilot.git
$ cd pteropilot
$ uv sync && uv run pteropilot
MCP config · claude_desktop_config.json 
{
  "mcpServers": {
    "pteropilot": {
      "command": "uvx",
      "args": ["pteropilot"],
      "env": {
        "PANEL_URL": "https://panel.example.com",
        "PANEL_API_KEY": "ptlc_xxxxxxxxxxxxxxxxxxxx",
        "PANEL_READONLY": "0"
      }
    }
  }
}

环境变量

  • PANEL_URL — 你的面板地址
  • PANEL_API_KEY — 面板 API Key
  • PANEL_READONLY — 设为 1 进入只读模式

用法

配好之后，直接说人话

「列出我所有服务器和状态」

「smp 服最近一次备份是什么时候？没有就现在建一个」

「往 creative 服上传这个插件并重启」

命令行

不想开 AI？直接命令行也一样

广播通知、批量重启这些事，写进 cron 或计划任务就行。不用起 MCP 客户端，跑一条就退出。

广播一条指令 
# 只发给 running 的服务器
$ pteropilot --broadcast "say 服务器 5 分钟后重启"

# 普通指令免确认；高危指令要 --confirm
$ pteropilot --broadcast "whitelist add Steve"
$ pteropilot --broadcast "stop" --confirm

# 等到点再发（cron 表达不了「先等一会儿」时用）
$ pteropilot --broadcast "say 马上回来" --in 5m
$ pteropilot --broadcast "say 关门了" --at 03:00

# 给脚本看的结果
$ pteropilot --broadcast "say hi" --json

高危指令（stop / kill / op / ban / whitelist off 等）不带 --confirm 会被直接拒掉。退出码：0 全部发出、1 有失败、2 用法错、3 被拦截。

批量电源 
# start 免确认
$ pteropilot --power start --servers smp,creative

# stop / restart / kill 要 --confirm
$ pteropilot --power restart --servers smp --confirm

# "*" = 全部服务器，这种也要确认
$ pteropilot --power stop --servers "*" --confirm

# 等到 3 点再重启（< 24 小时）
$ pteropilot --power restart --servers smp --confirm --at 03:00

--servers 必填。电源是写操作，它不会替你猜范围——避免「以为只发一台、结果发了全部」。

看状态 · 不开 AI 
# 全部服务器：状态 / 健康度 / CPU / 内存
$ pteropilot --status

# 单台：额外读日志推断在线玩家数
$ pteropilot --status smp

# 退出码分流：0 全部健康 / 1 有服务器异常 / 2 参数错 / 3 配置错 / 4 面板不可达
$ pteropilot --status --json

# 盯着看：只在状态/健康/人数变化时刷屏，CPU 内存抖动不算；第二行起会显示「这台坏了多久」
$ pteropilot --status --watch --interval 10

# 备份是崩了之后才会想起来的东西：多一列「最新备份」，过期的单独点名
$ pteropilot --status --backups --backup-days 7

# 看到警告之后真正要问的是「哪个备份能拿来恢复」——直接列出来
$ pteropilot --backups smp --limit 10

# 恢复：按备份名取一次性下载链接（不必手打 36 位 UUID）
$ pteropilot --backup-url smp weekly-1

输出是一张表：标识、名称、🟢/🟡/🔴 健康度、CPU、内存。单台查询失败显示 ⚠ 且不盖住其他服务器；玩家数拿不到就显示 -，不编数字。

玩家活跃趋势 · 断网也能看 
# 本机哪些服务器有采样记录
$ pteropilot --players

# 单台：近 7 天在线时长排行 + 各时段活跃度
$ pteropilot --players smp

# 换窗口（1–365 天）与排行长度（1–100）
$ pteropilot --players smp --days 30 --top 20

# 机器可读，方便接 Grafana / 自建面板
$ pteropilot --players smp --json

# 崩服时别反复手动重跑：跟读日志，只打新增行（Ctrl+C 退出）
$ pteropilot --log smp --watch

# 只用命令行也想攒历史：现在就采一条（可挂 cron；cron 停了 --doctor 会发现）
$ pteropilot --players --record
看控制台 · 崩了先看这里 
# 末 80 行控制台输出
$ pteropilot --log smp

# 往前翻更多（1–2000 行）
$ pteropilot --log smp --lines 300

# 只看报错行（不区分大小写）
$ pteropilot --log smp --grep error

# 多台一起看：* 是全部，也可以写 a,b
$ pteropilot --log "*" --grep error

# 机器可读；grep 命中 0 行时退出码 1，可写等待脚本
$ pteropilot --log smp --grep Started --json

输出前会清掉 ANSI 颜色和回车符，管道或粘贴都不会乱。没有内容可显示时退出码 1（空控制台 / grep 没命中），参数写错是 2。

数据来自本机采样文件（每次 list_players 记一条），不经过面板 API——所以不需要配置、不需要联网，面板挂了也能看历史。还没有采样时退出码是 1，方便 cron 区分「没数据」和「出故障」。

放进 cron：每晚 3 点重启 
# 提前 5 分钟喊话，整点重启
55 2 * * *  pteropilot --broadcast "say 5 分钟后重启"
0 3 * * *   pteropilot --power restart --servers "*" --confirm

面板地址和 Key 走环境变量（PANEL_URL / PANEL_API_KEY），cron 里记得带上；或者写进 ~/.config/pteropilot/。

告警：活着但快撑不住也通知 
# 原来只看「在不在线」；一台 running 但 CPU 打满的服务器它不会叫
$ pteropilot-alerts --webhook "https://..." --cpu 85 --memory 90

# 备份超过 7 天没更新（或从来没有）也推一条——这个不打没人会主动看
$ pteropilot-alerts --webhook "https://..." --backup-days 7

# 三个阈值都能按服务器单独调（~/.pteropilot/alerts.json）
#   "servers": { "heavy-pack": { "cpu_threshold": 97 },
#                "tiny-lobby": { "cpu_threshold": 60, "backup_days": 2 } }

CPU 是绝对值百分比；内存是使用率（memory_bytes / memory_limit），面板不限额的服务器自动跳过该项，不会拿 0 当分母算出假百分比。等于阈值就告警（到 85 就叫，不是超过 85）。默认 0 = 关闭。

安全

Key 不出本机

  • API Key 只保存在你本机的客户端配置里，仅用于直接请求你的面板，不经过任何第三方服务器。
  • 不放心就开 PANEL_READONLY=1，AI 只能看不能动。
  • 建议给 AI 使用权限最小化的 API Key。
  • 同时支持 Pterodactyl v1 与 Pelican；所用 API 端点与 payload 形状已对照 Pelican 源码核实。

FAQ

常见问题

需要自己先装一个面板吗？

不需要。Pteropilot 连接你已经运行中的 Pterodactyl / Pelican 面板，只需要面板地址和 API Key。

支持哪些 AI 客户端？

任何支持 MCP 的客户端，例如 Claude Desktop、Cursor 等。

它会不会误删我的文件？

建议先开只读模式确认行为；高危操作需要二次确认；API Key 的权限也可以自行收窄到最小。

收费吗？

开源、免费，MIT 许可。源码在 GitHub，包在 PyPI。
