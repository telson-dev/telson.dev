SSH vs API

为什么不用「直接 SSH 执行命令」？

给 AI 一把 root，和给它一把有权限范围的 API Key，是两件完全不同的事。

01

面板用户本来就没有 shell

Pterodactyl / Pelican 的典型用户拿到的是面板账号和受限 API Key，而不是节点上的 root。面板存在的意义就是把操作系统隔离掉。

02

最小权限

只读模式、危险操作二次确认、权限边界由 API Key 决定。AI 只能做你允许它做的事，而不是拥有一台机器的全部能力。

03

该走 API 的就走 API

备份、文件、电源状态在面板里都是有权限、有审计、有状态语义的一等操作，不是随手一条 shell 命令。

开始使用

三分钟接入

需要 Python 3.12+。用 uv 一行跑起来，然后在 MCP 客户端里加一段配置即可。

命令行 
# 需要 Python 3.12+ 与 uv
$ uvx pteropilot
  • API Key 在面板的 Account → API Credentials 里生成
  • 先用只读模式跑一遍，确认行为符合预期再放开

从源码运行（开发者）

# 需要 git、uv 与 Python 3.12+
$ git clone https://github.com/telson-dev/pteropilot.git
$ cd pteropilot
$ uv sync && uv run pteropilot
MCP config · claude_desktop_config.json 
{
  "mcpServers": {
    "pteropilot": {
      "command": "uvx",
      "args": ["pteropilot"],
      "env": {
        "PANEL_URL": "https://panel.example.com",
        "PANEL_API_KEY": "ptlc_xxxxxxxxxxxxxxxxxxxx",
        "PANEL_READONLY": "0"
      }
    }
  }
}

环境变量

  • PANEL_URL — 你的面板地址
  • PANEL_API_KEY — 面板 API Key
  • PANEL_READONLY — 设为 1 进入只读模式

安全

Key 不出本机

  • API Key 只保存在你本机的客户端配置里，仅用于直接请求你的面板，不经过任何第三方服务器。
  • 不放心就开 PANEL_READONLY=1，AI 只能看不能动。
  • 建议给 AI 使用权限最小化的 API Key。
  • 同时支持 Pterodactyl v1 与 Pelican；所用 API 端点与 payload 形状已对照 Pelican 源码核实。

FAQ

常见问题

需要自己先装一个面板吗？

不需要。Pteropilot 连接你已经运行中的 Pterodactyl / Pelican 面板，只需要面板地址和 API Key。

支持哪些 AI 客户端？

任何支持 MCP 的客户端，例如 Claude Desktop、Cursor 等。

它会不会误删我的文件？

建议先开只读模式确认行为；高危操作需要二次确认；API Key 的权限也可以自行收窄到最小。

收费吗？

开源、免费，MIT 许可。源码在 GitHub，包在 PyPI。
